Real-Time GPS Auto Rickshaw Tracking & Direct Connect

A location-based service (LBS) built with Java 17, Spring Boot, Google Maps JavaScript API, and H2 JPA enabling direct passenger-to-driver contact without middleman commission or ride ordering friction.

🎯 1. Project Abstract & Objectives

Traditional ride-hailing applications (such as Uber and Ola) require complex in-app bidding, dynamic pricing surcharges, high commission deductions (20-30%), and mandatory ride-ordering transactions. Local auto-rickshaw commuters and students often just need to know: "Where is the nearest auto right now, and what is the driver's phone number so I can call them directly?"

Project Goals:

  • Eliminate middleman order transactions: Connect passengers directly with nearby registered auto rickshaws via live telephone and WhatsApp.
  • Display live GPS telemetry of all registered auto-rickshaws simultaneously on an interactive Google Map.
  • Implement mathematical Haversine Formula in Java to dynamically compute shortest surface distance and estimated time of arrival (ETA).
  • Support dynamic driver onboarding: Add new drivers to the fleet with immediate rendering on Google Maps.

📐 3. Distance Calculation: Haversine Algorithm

The Haversine formula determines the great-circle distance between two points on a sphere given their longitudes and latitudes. Implemented in DriverService.java:

public static double calculateHaversineDistance(double lat1, double lon1, double lat2, double lon2) { final int EARTH_RADIUS_KM = 6371; double dLat = Math.toRadians(lat2 - lat1); double dLon = Math.toRadians(lon2 - lon1); double a = Math.sin(dLat / 2) * Math.sin(dLat / 2) + Math.cos(Math.toRadians(lat1)) * Math.cos(Math.toRadians(lat2)) * Math.sin(dLon / 2) * Math.sin(dLon / 2); double c = 2 * Math.atan2(Math.sqrt(a), Math.sqrt(1 - a)); return EARTH_RADIUS_KM * c; }

🎓 5. College Viva Questions & Model Answers

Q1: How does this project differ from Uber or Ola?
Answer: Uber and Ola act as centralized booking brokers taking 20-30% commissions, requiring in-app digital payments and wait queues. Our system is a software-only Direct Connect & Live Tracking utility. Passengers see real-time moving rickshaws on Google Maps with direct phone and WhatsApp contact info, enabling direct street-fare or standardized meter negotiation with zero commission.
Q2: How is real-time location simulated and tracked?
Answer: The backend contains a scheduled service (SimulationService.java) executing periodic background threads using Spring's @Scheduled annotation. It models vehicle heading, speed variations, and road turn probabilities. Additionally, real drivers can transmit live physical coordinates via navigator.geolocation.watchPosition in driver-portal.html.
Q3: Why did you use Google Maps JavaScript API?
Answer: Google Maps provides industry-leading road network detail, landmark recognition, high-resolution satellite/street imagery, and powerful marker rendering capabilities. We customized it using SVG symbols with dynamic rotation matching vehicle headings.
Q4: How does data persistence work?
Answer: We use Spring Data JPA backed by H2 file-based storage (./data/autotrackdb). This ensures drivers added during presentations remain persisted even after application restarts, while offering a built-in web console at /h2-console for database inspections.
